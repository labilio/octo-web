# 返回会话模块时清除残留标题：设计规格

## 问题

用户打开一个会话后切换到通讯录、智能总结等一级模块，再返回会话模块。右侧会话视图已经被清空，但浏览器标题仍显示此前打开的会话名称。

根因是主界面会保留已访问模块的 React 实例，仅通过 `display: none` 隐藏。离开会话模块时，公共右侧路由被清空，但 `ChatVM.selectedConversation`、`WKApp.shared.openChannel` 和 `titleContextStore("chat")` 没有一起失效，造成页面状态与标题状态不一致。

## 目标行为

- 从会话切换到其他一级模块时，结束当前打开的会话页面状态。
- 同时清除选中会话、全局打开频道和会话标题上下文。
- 返回会话模块且用户尚未重新选择会话时，标题显示 `会话 - Octo`，并继续保留有效的未读会话数前缀。
- 用户重新选择私聊、群聊、Bot 或 Thread 后，标题按现有规则恢复为当前会话名称。

## 设计

`ChatVM` 订阅公共的 `wk:active-menu-changed` 事件。事件表明当前一级模块不再是 `chat` 时，调用一个幂等的会话页面重置方法：

1. 将 `selectedConversation` 设为 `undefined`，通过现有 setter 清理 `titleContextStore("chat")` 并刷新会话列表选中态。
2. 将 `WKApp.shared.openChannel` 设为 `undefined`，避免全局状态继续把旧频道当作当前打开会话。
3. 关闭只属于当前会话的设置面板状态。

右侧路由仍由主界面现有的菜单切换逻辑负责清空；`ChatVM` 不重复操作公共路由。返回 `chat` 时不自动恢复旧会话。

在 `didMount` 注册事件监听，在 `didUnMount` 对称注销，避免热更新或重复挂载产生多重监听。

## 不采用的方案

- 只清除标题上下文：会保留错误的选中会话和 `openChannel`，状态仍不一致。
- 返回时恢复旧会话：需要重建右侧路由和消息视图，属于另一项产品行为，不在本次修复范围。
- 在标题控制器里猜测右侧视图是否为空：会让通用标题层依赖聊天页面内部状态，破坏模块边界。

## 测试

新增 `ChatVM` 回归测试，覆盖：

- 已选择会话时切换到非 `chat` 模块，会清除选中会话、`openChannel` 和标题上下文。
- 在 `chat` 模块内部重复激活 `chat` 不清除当前会话。
- `didUnMount` 后事件不再影响该实例。
- 现有私聊、群聊、Bot、Thread 标题规则保持通过。
